# ADR-005: Dashboard Card to History Navigation (New Event vs Context Reuse)

## Context

The Dashboard macronutrient card must become clickable, navigating to the History tab with today's date pre-selected. We must decide:

1. **Shared ViewModel state**: Communicate via shared ViewModel (e.g., MealLoggingViewModel signal)
2. **Navigation arg**: Pass date as NavArg to HistoryRoute
3. **Composition event**: Emit callback; parent (MainActivity) handles routing
4. **Global state**: Use a single-use Flow or EventBus

## Decision

**Composition event** (callback from DashboardViewModel):
- `DashboardViewModel` receives callback `onMacroCardTapped: () -> Unit`
- Callback passed from MainActivity via viewModel factory or recomposition
- MainActivity handles routing: select History tab + pre-set HistoryViewModel to today's date
- Clean separation: Dashboard doesn't know about History; only signals intent

## Alternatives Considered

**Shared ViewModel state**
- ✅ Pro: Can pass data directly (date to select)
- ❌ Con: MealLoggingViewModel not right fit (for meal logging, not history navigation)
- ❌ Con: Would require new shared ViewModel; more complex DI

**Navigation arg**
- ✅ Pro: Type-safe via safeArgs
- ✅ Pro: Clear intent (navigation + payload)
- ❌ Con: No flexible callback; arg always passed, even if not needed
- ❌ Con: HistoryRoute must handle both "normal load" and "dashboard launch" flows

**EventBus/Flow (global state)**
- ✅ Pro: Decoupled; no parent coordination needed
- ✅ Pro: Scalable (any screen can trigger History)
- ❌ Con: Harder to test; non-deterministic event ordering
- ❌ Con: Requires new infrastructure (EventBus or Kotlin Flow channel)
- ❌ Con: Risk of event loss if History not subscribed

## Consequences

✅ **Benefits**:
- Simple, idiomatic Compose pattern (lambda callbacks)
- No new shared state; HistoryViewModel remains independent
- Easy to test (mock callback; verify called)
- MainActivity has full control over routing logic

⚠️ **Tradeoffs**:
- **Parent coordination**: MainActivity must be aware of Dashboard intent
- **No type-safety on payload**: Callback carries no data (date implicitly today)
- **Multiple callbacks**: If other screens trigger History, need separate signals (manageable)

✅ **Supports**:
- Dashboard card stays simple (no nav knowledge)
- HistoryViewModel init logic: pre-select today if launched from Dashboard
- Potential future: StatusBar tap also routes to History (same callback pattern)

## Notes

- Callback signature: `onMacroCardTapped: () -> Unit`
- MainActivity usage:
  ```kotlin
  val dashboardViewModel = viewModel(factory = DashboardViewModel.factory(appGraph) { 
      onMacroCardTapped = {
          // Select History tab
          currentTab.value = "history"
          // Pre-set HistoryViewModel to today
          historyViewModel.preSelectDate(LocalDate.now().toString())
      }
  })
  ```
- Visual feedback: Ripple + elevation on card tap (Material 3 default)
- Hint text: Optional subtle text on card "Tocca per visualizzare i dettagli" or similar
- Test: Verify callback invoked when card Surface clicked (Compose test via `performClick()`)
